# Strikethrough – site bundle

A static site: `index.html` plus two data files. No build step, so any static host works.

```
index.html          the whole site (styles and script inline)
data/deals.json     checked deals (regenerated by build.py)
data/calendar.json  retailer sale dates
```

## Live address

https://strikethrough.com.au (hosted on Netlify)

## Go live today (about 15 minutes)

1. **Domain.** Check `strikethrough.com.au` (and `.com`) at any registrar, such as VentraIP, Crazy Domains or GoDaddy. A `.com.au` needs your ABN.
2. **Host.** Either:
   - **Fastest:** go to app.netlify.com/drop and drag this folder in. You get a live URL straight away.
   - **Best (auto-updating):** put this folder in a new GitHub repo, then import the repo in Vercel or Netlify. Every time the data files change in the repo, the site redeploys itself.
3. **Point the domain.** In Vercel or Netlify, add the custom domain and copy the DNS records it gives you into your registrar.
4. **Sign-ups** use Netlify Forms automatically on Netlify: submissions appear under the site's Forms tab, where you can turn on email notifications. To use Mailchimp or Klaviyo instead, paste a form URL into `formEndpoint` near the bottom of `index.html`.
5. **Analytics.** Paste your GA4 or Plausible snippet into the `<head>`.

## Product art

`art/` holds one drawing per category (made by `make_art.py`), shown on cards until a deal has a real product image from an affiliate feed (the 13th field in `raw_deals.json`). New categories need a drawing added to `make_art.py`.

## Analytics

Google Tag Manager (GTM-N8LGLSV5) is installed on every page. The site pushes two events to the dataLayer: `retailer_click` (with `retailer`, `product`, `verdict`, `affiliate`, `link_kind`) and `sign_up` (with `method`). GA4 (G-DBGC2DTVBK) loads directly on every page and receives the same two events, so don't also add a Google tag for that ID inside Tag Manager or visits will be counted twice. Tag Manager is there for other tags (Meta pixel, ad conversions).

## Affiliate links

Edit `affiliates.json` on GitHub (pencil icon, then Commit changes). The site picks it up within a minute or two.

- **Amazon Associates:** put your tracking ID (it looks like `yourname-22`) in `amazon_tag`.
- **Commission Factory and similar networks:** join the retailer in your dashboard, copy its tracking link, and paste it into that retailer's `template` with `?Url={url}` on the end, for example `https://t.cfjump.com/12345/t/67890?Url={url}`. The site swaps `{url}` for each product link.

Affiliate links get `rel="sponsored"`, and the disclosure line appears automatically once any retailer is switched on.

## Keeping the data fresh

A scheduled refresh runs twice a day and commits new data here. By hand: edit `raw_deals.json` (optional 12th and 13th fields on a deal are its exact product URL and a product image URL from an affiliate feed), then run `python3 build.py && python3 build_calendar.py && python3 build_pages.py`. That writes `data/deals.json`, `data/calendar.json`, appends to `data/history.json` (our own price record), and rebuilds the category pages, `sitemap.xml` and `robots.txt`.

## Before launch

- Have the "How we check" wording and verdict labels read over for legal risk, since the site names retailers.
- Once the site is live, apply to the affiliate networks (Commission Factory, Amazon Associates AU and others). They review your live site before approving you.

## Share images

`og/*.jpg` are the 1200x630 preview cards that show when a link is shared (Facebook, LinkedIn, iMessage, Slack). Text is evergreen, so they only need regenerating when a category is added or the design changes: `python3 make_og.py` (needs Playwright).

## Community votes (OzBargain)

`raw_deals.json` has a `community` block keyed `"<product key>|<retailer>"`, each `{votes, url, posted, checked}` pointing at the OzBargain post. `build.py` turns it into `community_votes` / `community_url` on each row and adds a small score boost (+1, +3 at 100+ votes, +5 at 300+) unless the deal already has a price catch. The site shows an "On OzBargain" badge (🔥 "Hot" at 300+), links to the discussion, and has a "Most votes on OzBargain" sort. The scheduled refresh updates vote counts from https://www.ozbargain.com.au/deals.

## Hosting on Cloudflare Workers (from 27 Nov 2026)

- Worker "strikethrough", connected to this repo (Workers Builds): build command `exit 0`, deploy command `npx wrangler deploy`. Every push to `main` redeploys.
- `wrangler.jsonc` serves the repo root as static assets; `.assetsignore` keeps internal files (worker code, Python, README, runbook) from being served. `_headers` sets the 5-minute cache on /data/*.
- Sign-up forms post to `/api/subscribe` (worker/api/subscribe.js), stored in the KV namespace bound as `SIGNUPS` (auto-created on first deploy).
- Download sign-ups: `https://strikethrough.com.au/api/export?key=<EXPORT_KEY>` (add `&form=verified-list` or `&form=signup`). EXPORT_KEY is a secret set under the Worker's Settings → Variables and Secrets.

## Check a deal, price-drop alerts, OzBargain feed

- **Check a deal** (hero): matches a typed product or a pasted retailer link to tracked products, client-side. Misses can be sent as a check request (`form-name=check-request`, email optional) to `/api/subscribe`.
- **Price-drop alerts**: the deal story has an "Alert me" form (`form-name=watch`). Watches are stored as KV keys `watch:<product_key>:<id>` with the details in metadata. A cron in `wrangler.jsonc` runs `worker/alerts.js` at 7am and 7pm Sydney time and emails anyone whose product is now at least 3% (and $1) below the price when they set the alert, via Resend. Each email has a one-click unsubscribe (`/api/unwatch`).
  - To switch sending on: create a free Resend account, verify `strikethrough.com.au` there (it gives DNS records to add in Cloudflare), then add Worker secrets `RESEND_API_KEY` and optionally `ALERT_FROM` (default `Strikethrough <alerts@strikethrough.com.au>`). Until then the job does nothing and watches simply accumulate.
- **Exports**: `/api/export?key=<EXPORT_KEY>&form=check-request` and `&form=watch` list requests and alerts.
- **OzBargain feed**: `.github/workflows/ozbargain.yml` runs `scripts/ozb_feed.py` every 4 hours and commits `data/ozb_feed.json` when it changes. The site uses it to keep vote counts current.

## Install and share to Strikethrough

- `manifest.webmanifest`, `sw.js` (caches nothing) and `icons/` make the site installable. On Android (Chrome, Samsung Internet) the installed app appears in the share menu: sharing a product page from any store's app opens `/share/`, which hands the link to the Check a deal box via `/?check=…`.
- The Check box shows "add Strikethrough to your phone" when the browser offers installation, and a "Check on Strikethrough" bookmarklet on desktop. iPhones don't support web share targets, so on iOS the bookmarklet or pasting a link is the way in.
- `/?check=<product or link>` works as a plain link too.

## SEO

- `build_pages.py` writes, from `data/deals.json`: a page per category (`/deals/<category>/`), a price-check page per product (`/price/<product_key>/`, comparing every store we track, with Product + AggregateOffer and BreadcrumbList structured data), static category and popular-product links into the homepage footer (between `<!--SEO-LINKS-->` markers), `sitemap.xml` and `robots.txt`. It runs in every refresh, so pages stay current and pages for products no longer tracked are removed.
- Homepage has WebSite and Organization structured data. `404.html` is served for unknown URLs (`not_found_handling` in `wrangler.jsonc`).
- When the site switches to year-round mode after Cyber Monday, update the homepage `<title>`, description and og tags, and the "Black Friday" wording in `build_pages.py` category titles.
